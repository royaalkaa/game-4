# Фото-батлы: спецификация

Веб-приложение для мероприятий. На экране зала идёт батл, гости заходят с телефона по QR-коду и голосуют в дуэлях 1 на 1, победитель проходит дальше до финала. Аудитория: сотни своих людей в одном зале.

## Решено

- Фото загружает только админ. Приём фото от пользователей не делаем.
- Только веб, без Телеграма.
- Нагрузка: сотни зрителей, единицы батлов одновременно.
- Батл идёт на мероприятии, вход по QR. Регистрации нет.

## Вход по QR

- На экране зала показывается QR со ссылкой на батл и кодом входа. Код меняется каждые 30 секунд, старый действует ещё 30 секунд. Ссылку, пересланную в чат, через минуту открыть уже нельзя: голосуют только те, кто в зале.
- По коду сервер выдаёт гостю анонимный токен в cookie на срок батла. Один токен = один голос в дуэли.
- Повторный вход через инкогнито возможен только повторным сканированием в зале. Для своих людей этого достаточно.
- Лимита голосов по IP нет: весь зал сидит на одном Wi-Fi и выходит в сеть с одного адреса. Лимит запросов по IP только против спама запросами, с запасом на сотни людей.
- Строгий режим (на потом): админ печатает персональные одноразовые QR на бейджи, тогда один человек = один голос жёстко.

## Открытые вопросы

- [ ] **Где хостить.** Сервер, домен, HTTPS. В зале нужен интернет или локальный сервер в той же сети. В спецификацию не входит, пока не решено.
- [ ] **Подпись под фото после раунда:** показываем имя автора или только «Фото №3»?

## Правила игры

- Батл: название, тема, 4, 8 или 16 фото, длительность раунда, длительность заморозки (по умолчанию 10 минут).
- Если фото не степень двойки, лишние получают проход в следующий раунд без дуэли.
- Пары первого раунда случайные (`secrets`, не `random`).
- Все дуэли раунда идут одновременно и заканчиваются в одно время. Раунд на мероприятии длится минуты, не часы.
- Следующий раунд запускает ведущий кнопкой, чтобы успеть объявить результаты. Можно включить автостарт.
- Финал можно провести одной дуэлью на весь зал: остальные раунды уже закрыты, все смотрят на экран.
- Голос: один на дуэль, изменить нельзя.
- Счёт дуэли виден только тем, кто уже проголосовал. До голоса видно лишь «проголосовало N человек».
- За время заморозки до конца раунда счёт скрыт у всех, кроме админа.
- Ничья: побеждает фото, которое первым набрало итоговое число голосов.
- Пустая дуэль (0 голосов): победитель выбирается случайно, в итогах помечено «по жребию».
- Админ может остановить батл и снять фото (жалоба, ошибка). Снятое фото проигрывает текущую дуэль.

## Экраны

Каждый экран обрабатывает четыре состояния: загрузка, пусто, ошибка, нет прав.

| Экран | Главное действие |
| --- | --- |
| Экран зала (проектор): QR, таймер, текущие дуэли, сетка, объявление победителя дуэли и батла крупно | Нет действий, только показ; управляет админ |
| Главная на телефоне: текущий батл, раунд, таймер | Перейти к голосованию |
| Дуэль: два фото рядом (на телефоне друг под другом) | Выбрать фото |
| Сетка турнира | Открыть дуэль |
| Итоги батла: победитель, путь по сетке, счёт всех дуэлей | Поделиться ссылкой |
| Админ: создать батл, загрузить фото, запустить | Запустить батл |
| Админ: ход батла, живой счёт, снять фото | Следующий раунд |

После голоса зритель сразу видит следующую дуэль раунда, за которую ещё не голосовал. Пролистать раунд должно занимать меньше минуты.

## Данные

- `battle`: id, title, theme, status (draft, active, finished, stopped), round_minutes, freeze_minutes, created_at
- `photo`: id, battle_id, file_key, caption, width, height
- `match`: id, battle_id, round, slot, photo_a_id, photo_b_id (null = проход без дуэли), starts_at, ends_at, winner_id, decided_by (votes, tie, lot, removal)
- `join_code`: battle_id, code_hash, valid_until
- `voter`: id, battle_id, token_hash, created_at
- `vote`: id, match_id, voter_id, photo_id, created_at; уникальность (match_id, voter_id)
- Миграции только добавочные, линейной цепочкой.

## Ограничения и безопасность

- Фото: JPEG, PNG, WebP; до 10 МБ; до 8000 px по стороне; формат проверяется по содержимому, не по расширению. Имя файла на диске генерирует сервер.
- Вход админа: пароль из env, хранится хешем; cookie `HttpOnly`, `Secure`, `SameSite=Lax`. Ограничение попыток входа.
- Голосование: голос без токена или после `ends_at` отклоняется сервером, таймер на клиенте только для показа. Коды входа и токены хранятся хешем, генерируются через `secrets`.
- Счёт в период заморозки не отдаётся API вообще, а не прячется на фронте.
- Ошибки API: текст для человека (`UserFacingError`), без `str(exc)`. Логи через `structlog` с `request_id`, без IP целиком.
- Секреты только в env. Запреты DerScanner из правил действуют.

## Итерации

### 1. Батл без голосующих: админ создаёт и запускает

- **Зачем:** без сетки и таймеров голосовать не за что; это ядро логики.
- **Что делаем:** модели и миграции, вход админа, загрузка фото, создание батла, построение сетки, смена раундов по времени, экран сетки (только просмотр).
- **Критерий приёмки:** админ загружает 8 фото, запускает батл с раундом 2 минуты и автостартом раундов; через 6 минут батл в статусе finished, у каждой дуэли есть победитель с `decided_by = lot`; 5 фото дают сетку с 3 проходами без дуэли.
- **Тесты:** построение сетки для 2, 5, 8, 16 фото; смена раунда на границе `ends_at`; отклонение файла с подменённым расширением и файла больше лимита; EXIF удалён.
- **Что получится:** работающий турнир, который проходит сам по таймеру.

### 2. Голосование

- **Зачем:** главная функция для зрителей.
- **Что делаем:** экран зала с меняющимся QR, вход по коду, экран дуэли, голос, переход к следующей дуэли, счёт после голоса, кнопка «Следующий раунд», опрос раз в 5 секунд.
- **Критерий приёмки:** телефон сканирует QR с экрана и попадает в дуэль меньше чем за 10 секунд; код старше минуты отклоняется; второй голос того же токена в той же дуэли отклоняется; до голоса API не отдаёт счёт; голос после конца раунда отклоняется; 300 голосующих с одного IP голосуют без отказов.
- **Тесты:** срок действия кода; уникальность голоса, в том числе при двух одновременных запросах; правило ничьей; доступ к счёту до и после голоса; нагрузочный прогон 300 голосов за минуту.
- **Что получится:** полный батл на мероприятии: экран в зале, голоса с телефонов.

### 3. Интрига

- **Зачем:** без неё батл превращается в обычный опрос.
- **Что делаем:** заморозка счёта, экран итогов с путём победителя по сетке, ссылка на итоги, превью ссылки (Open Graph с фото победителя).
- **Критерий приёмки:** за `freeze_minutes` до конца раунда API не отдаёт счёт никому, кроме админа; ссылка на итоги в мессенджере показывает картинку и название батла.
- **Тесты:** граница заморозки; выдача счёта админу и зрителю в период заморозки.
- **Что получится:** финал, который ждут, и итоги, которые пересылают.

### 4. Прогнозы

- **Зачем:** у зрителя появляется свой интерес на весь батл, а не на одну дуэль.
- **Что делаем:** до конца первого раунда зритель выбирает будущего победителя; после финала таблица угадавших.
- **Критерий приёмки:** прогноз после конца первого раунда отклоняется; таблица совпадает с фактическим победителем.
- **Тесты:** окно приёма прогноза; подсчёт угадавших.
- **Что получится:** причина вернуться к финалу.
